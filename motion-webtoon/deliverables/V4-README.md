# 모션 웹툰 V4

1920×1080, 30fps, 정확히 15초, 450프레임, H.264 MP4. 음성·음악 없음.

- `webtoon-v4-15s.mp4`: 최종 영상
- `scene-1-v4-test-2s.mp4`: 잔상을 수정하고 검토한 1번 장면 테스트
- `webtoon-v4-download.zip`: 위 두 영상과 검증 결과의 다운로드 사본
- `webtoon-v3-15s.mp4`: 이전 버전 보존본

## 소재와 연출

GitHub main의 `public/assets/keyframes-v3/generated-originals/`에서 다음 원본을 사용했다.
`scene-1.png`, `scene-2-refined.png`, `scene-3.png`, `scene-4-refined.png`,
`scene-5-refined.png`, `scene-6-refined.png`.
원본 파일을 수정하지 않았으며 정면 캐릭터 시트나 다른 배경을 사용하지 않았다.

| 시간 | 연출 |
|---|---|
| 0–2초 | 생각풍선 등장, 물방울의 미세한 형태 변화, 작은 화면 확대 |
| 2–4초 | 타워 건물 고정, 원본 장갑 두 개의 안내 손짓, 캡슐 장갑 반응 |
| 4–6.5초 | 0.4초 대기 뒤 캡슐·손·내부 장비 전체가 아래로 가속. 추진 연출 없음 |
| 6.5–9초 | 놀란 얼굴·챔버·플레이트·물방울 고정, 구형 물방울 강조, 미세중력 표기 |
| 9–12초 | 카메라 표시등, 모니터 관측 강조, 플레이트 장갑의 작은 반응 |
| 12–15초 | 세 캐릭터 원본 장갑의 짧은 축하 손짓, 결과의 순차 강조. 14–15초 정지 |

원본의 픽셀을 마스크로 분리해 `public/assets/motion-v4/`에 저장했다.
가려진 영역은 이미지 편집 도구로 복원했다. 1·2·5·6번은 분리 영역에만
복원 픽셀을 사용한다. 3번은 캡슐이 빠진 자리의 윤곽 경계를 없애기 위해
같은 통로의 연속된 복원 배경을 사용한다. 캐릭터·캡슐 내부 장비는 원본 픽셀이다.
복원 배경과 원본 외곽선 분리는 640px 검토용 사본과 렌더 프레임으로 확인했다.

모든 모션은 Remotion 프레임 기반이다. 별도 JSON 자막과 번들 한글 폰트를 사용한다.

## 실행

프로젝트 폴더에서:

```sh
npm ci
npm run lint
npm run render:v4-test
npm run render:v4
python tools/verify-v4.py
```

현재 `remotion.config.ts`는 `/usr/bin/chromium`을 사용한다. 다른 환경에서는
설치된 Chromium 경로를 지정하거나 해당 설정을 제거해 Remotion 브라우저를 사용한다.

원본 기반 소재 재분리에는 Pillow, NumPy, OpenCV가 필요하다.
`python tools/prepare-v4-assets.py`는 저장된 복원본과 마스크 설정을 사용하며,
중립 위치 재합성이 원본과 일치하는지 확인한다. 완성 소재는 이미 저장되어 있어
일반 렌더링에는 Python이 필요하지 않다.

## 검증

코드 검사·타입 검사 통과. 테스트는 60프레임/2초, 최종본은 450프레임/15초이며
모두 전체 디코딩을 통과했다. 최종 장면의 420·449프레임을 별도로 렌더링해
픽셀 동일성을 확인했다. 손 연결부, 풍선 등장, 낙하 중간·종료, 자막 위치도 확인했다.
상세 규격과 용량은 `v4-validation.json`에 저장한다.
